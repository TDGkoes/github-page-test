# RFP-02. 가상 생활서비스 통합 채널 구축

> 합성 테스트 문서입니다. 기관명, 수치, 시스템, 일정은 모두 가상이며 실제 고객·사업과 무관합니다.

## 테스트 메타정보 (RFP 본문 외)

### Microsoft 서비스·기술 기준

이 기준은 Microsoft 제품·서비스 및 개발 기술로 요구 기능을 구현할 수 있는지 평가하기 위한 테스트 전제입니다. Microsoft 제품이 제공하는 기능의 범위와 제안사의 구축·운영 인력 제공 여부는 별개로 판단합니다.

- 외부 이용자용 웹 채널은 Power Pages와 Dataverse를 후보로 검토하고, 내부 업무 화면은 Power Apps, 자동화는 Power Automate를 후보로 검토한다.
- 고객·외부 사용자 인증은 Microsoft Entra External ID, 기관 사용자 인증은 기관의 Entra ID 또는 제공된 OIDC 구성과의 연계를 검토한다.
- SMS 발송은 Azure Communication Services를 후보로 검토할 수 있다. 발신 번호·지원 지역·사용량·동의 및 메시지 정책, 비용과 서비스 변경 공지를 확인해야 한다. 결제는 외부 PG 계약과 API가 있어야 연계 가능하며 Microsoft 제품의 기본 결제 기능으로 간주하지 않는다.
- 네이티브 앱은 .NET MAUI를 이용한 사용자 지정 개발이 가능하다. iOS 빌드에는 Mac이 필요하며, 앱스토어 계정·심사·배포 정책 및 지속 운영은 각 플랫폼과 발주기관 조건에 달려 있다.
- 키오스크·생체인식 장치 공급, 현장 설치·보증은 Microsoft 서비스 기능이 아니다. 웹 접근성은 구현·검증의 대상이며 제품 사용만으로 준수 인증이나 결과가 보장되지는 않는다.

### 분류 기준

- **지원 범위 내**: 관련 Microsoft 제품의 문서화된 기능으로 요구사항을 직접 구현할 수 있고 필수 전제조건이 명시되어 있음
- **일부 지원 가능**: Microsoft 제품을 기반으로 구현할 수 있으나 사용자 지정 개발, 외부 연계, 추가 라이선스, 외부 계약, 지역·용량 확인 또는 별도 검증이 필요함
- **지원 불가**: Microsoft 제품·서비스만으로 충족할 수 없는 하드웨어 공급·현장 서비스 또는 무오류·절대 성과 보장이 핵심 조건임

각 분류에 Microsoft 제품·기능 근거, 전제조건, 라이선스·외부 의존성, 확인 질문을 함께 제시합니다. 제품명만으로 지원을 확정하지 말고 현재 GA/Preview 상태와 지역 가용성을 확인합니다. 아래 요구사항에는 정답 라벨이 포함되어 있지 않습니다.

## 1. 사업 개요

### 1.1 발주기관

가상 공공서비스 운영기관 **새결생활지원원**

### 1.2 사업명

생활지원 신청·조회 통합 웹 채널 구축

### 1.3 추진 배경

새결생활지원원은 주민이 여러 부서에 전화하거나 각기 다른 웹페이지를 방문해 지원 서비스를 신청하는 불편을 줄이려 한다. 신청 안내, 온라인 접수, 처리 상태 조회를 단일 웹 채널에서 제공하고자 한다.

### 1.4 사업 목표

- 지원 서비스와 신청 절차를 한 화면에서 안내한다.
- 주민이 온라인으로 신청하고 처리 상태를 확인할 수 있게 한다.
- 담당자가 신청 현황과 미처리 업무를 관리할 수 있게 한다.

## 2. 사업 범위

- 서비스 이용자와 담당자의 업무 흐름 분석
- 반응형 웹 포털 및 운영자 화면 구축
- 서비스 안내, 신청서 작성, 접수 확인, 처리 상태 조회 기능
- 기관 계정 및 외부 서비스 연계 검토
- 테스트, 운영자 교육, 사용자 문서 작성

## 3. 요구사항

| ID | 요구사항 |
|---|---|
| SVC-01 | PC와 모바일 브라우저에서 서비스 안내, 신청, 접수 확인, 처리 상태 조회가 가능한 반응형 웹 채널을 구축한다. |
| SVC-02 | 담당자가 서비스 종류, 신청 기간, 필수 서류 안내문을 관리할 수 있는 운영자 화면을 제공한다. |
| SVC-03 | 기관이 제공하는 OIDC 설정과 테스트 계정을 사용해 담당자 로그인 및 역할별 관리 기능을 연계한다. |
| SVC-04 | 신청 현황을 서비스 종류, 접수일, 처리 상태별로 조회하고, 권한이 있는 담당자가 결과를 CSV로 내려받을 수 있게 한다. |
| SVC-05 | 문자 알림과 온라인 수수료 결제를 연계한다. 발주기관은 현재 이용할 외부 사업자와 계약 여부를 확정하지 않았고, API 명세 및 테스트 계정도 아직 제공하지 않았다. |
| SVC-06 | 기존 부서별 신청 시스템의 신청 내역을 통합한다. 일부 시스템은 인터페이스 문서가 없고 담당 부서와 데이터 항목이 확정되지 않았다. |
| SVC-07 | 동일한 기능을 네이티브 iOS 및 Android 앱으로 개발하고, 앱스토어 심사·등록 및 향후 앱 버전 업데이트를 수행한다. 발주기관은 개발자 계정과 심사에 필요한 사업 정보를 제공할 수 있다. 웹 채널 또는 대체 방식은 허용하지 않는다. |
| SVC-08 | 주민센터에 설치할 무인 신청 키오스크 80대와 지문·얼굴 인식 장치를 사업자가 제조·조달하고, 설치와 현장 보증을 제공한다. |
| SVC-09 | 사용자가 보조기술을 이용해 주요 신청 흐름을 이용할 수 있도록 웹 화면 접근성을 고려하고, 테스트 결과와 개선 내역을 제출한다. |
| SVC-10 | 접수 오류가 절대로 발생하지 않고, 모든 신청이 법정 기한 안에 처리되도록 사업자가 결과를 보장한다. |

## 4. 비기능 요구사항

- 주민 화면은 한국어를 기본으로 하며, 다국어 제공 여부는 제안사가 범위와 전제조건을 구분해 제시한다.
- 개인정보가 포함될 수 있는 신청 화면은 최소 수집과 역할별 접근을 고려한다.
- 발주기관의 보안·개인정보 처리 기준은 착수 후 제공될 예정이다.
- 운영 환경과 외부 서비스 계약 조건은 발주기관이 확정한다.

## 5. 수행 및 제안 요청

제안사는 요구사항별 대응 방안, 웹 채널과 별도 플랫폼의 경계, 외부 서비스·부서 시스템의 선행 조건, 개인정보 관련 확인 사항, 테스트 및 접근성 검증 방법을 제시한다. 미확정된 사업자·계약·인터페이스는 확정된 전제로 작성하지 않는다.
