# RFP-01. 가상 물류 운영 포털 구축

> 합성 테스트 문서입니다. 기관명, 수치, 시스템, 일정은 모두 가상이며 실제 고객·사업과 무관합니다.

## 테스트 메타정보 (RFP 본문 외)

### Microsoft 서비스·기술 기준

이 기준은 Microsoft 제품·서비스 및 개발 기술로 요구 기능을 구현할 수 있는지 평가하기 위한 테스트 전제입니다. Microsoft 제품이 제공하는 기능의 범위와 제안사의 구축·운영 인력 제공 여부는 별개로 판단합니다.

- 업무 앱은 Power Apps와 Dataverse, 업무 흐름은 Power Automate, 분석 화면은 Power BI를 후보로 검토한다.
- 문서에서 인쇄·손글씨 텍스트와 구조를 추출하는 기능은 Azure Document Intelligence에서 제공한다. 문서 종류·품질별 샘플 검증, 필요한 경우 사용자 지정 모델 학습, 신뢰도 기준 및 사람의 예외 검수가 필요하며 정확한 추출을 보장하지 않는다.
- 기존 ERP/API 연계와 데이터 이관은 커넥터, 사용자 지정 커넥터 또는 API 기반으로 검토할 수 있다. 인터페이스 명세·접근 권한·테스트 환경·데이터 매핑·품질 기준과 필요한 라이선스가 전제된다.
- Microsoft 클라우드 서비스의 가용성 및 지원 조건은 제품별 SLA·지원 계약을 확인한다. 이는 발주기관 창고의 상주 인력, 24x7 운영대행, 장비 조달·수리·보증을 의미하지 않는다.

### 분류 기준

- **지원 범위 내**: 관련 Microsoft 제품의 문서화된 기능으로 요구사항을 직접 구현할 수 있고 필수 전제조건이 명시되어 있음
- **일부 지원 가능**: Microsoft 제품을 기반으로 구현할 수 있으나 사용자 지정 개발, 외부 연계, 추가 라이선스, 데이터 준비, 지역·용량 확인 또는 별도 운영 서비스가 필요함
- **지원 불가**: Microsoft 제품·서비스만으로 충족할 수 없는 하드웨어 공급·현장 서비스 또는 100% 정확도·무중단과 같은 절대 결과 보장이 핵심 조건임

각 분류에 Microsoft 제품·기능 근거, 전제조건, 라이선스·외부 의존성, 확인 질문을 함께 제시합니다. 제품명만으로 지원을 확정하지 말고 현재 GA/Preview 상태와 지역 가용성을 확인합니다. 아래 요구사항에는 정답 라벨이 포함되어 있지 않습니다.

## 1. 사업 개요

### 1.1 발주기관

가상 물류기업 **모람로지스**

### 1.2 사업명

창고·배송 업무를 위한 물류 운영 포털 구축

### 1.3 추진 배경

모람로지스는 창고별 재고 확인, 출고 요청, 배송 이슈 접수를 여러 문서와 메신저로 처리하고 있다. 처리 현황을 한곳에서 조회하고 반복 업무를 줄일 수 있는 내부 업무 포털을 도입하려 한다.

### 1.4 사업 목표

- 출고 요청부터 처리 완료까지 상태를 일관되게 관리한다.
- 사용자 역할에 따라 업무와 정보 접근을 통제한다.
- 운영 현황과 주요 지연 항목을 조회한다.

## 2. 사업 범위

- 업무 절차 확인 및 목표 업무 흐름 정의
- 브라우저 기반 업무 포털 설계·개발
- 사용자·역할 관리, 출고 요청, 배송 이슈 접수 및 상태 관리
- 운영 현황 대시보드
- 합의된 데이터 및 시스템 연계 검토
- 테스트, 운영자 교육, 사용자·관리자 문서 작성

## 3. 요구사항

| ID | 요구사항 |
|---|---|
| LOG-01 | 착수 후 현행 출고 요청 및 배송 이슈 처리 절차를 인터뷰하고, 담당자 검토를 거쳐 목표 업무 흐름과 용어 정의서를 작성한다. |
| LOG-02 | PC와 태블릿의 최신 브라우저에서 사용할 수 있는 내부 업무 포털을 제공하고, 출고 요청의 등록·조회·수정·승인·완료 처리를 구현한다. |
| LOG-03 | 사용자 역할별 메뉴와 데이터 접근 권한을 설정하고, 주요 상태 변경 이력을 조회할 수 있게 한다. |
| LOG-04 | 창고별 미처리 요청, 처리 상태, 지연 건수를 조건별로 조회하는 운영 대시보드와 CSV 다운로드를 제공한다. |
| LOG-05 | 모람로지스 ERP와 출고 정보를 연계한다. 발주기관은 REST API 명세, 테스트 계정 및 테스트 환경을 제공하며, 인터페이스 범위는 착수 후 확정한다. |
| LOG-06 | 기존 재고 데이터를 신규 시스템으로 이관한다. 발주기관은 데이터베이스 스키마와 CSV 추출본을 제공하되, 코드 매핑과 오류 데이터 정제 기준은 착수 후 협의한다. |
| LOG-07 | 과거 수기 출고전표의 스캔 이미지에서 주요 항목을 추출한다. 착수 후 대표 샘플로 판독 결과를 검증하고, 신뢰도가 낮거나 필수 항목이 누락된 건은 담당자가 확인하도록 한다. |
| LOG-08 | 서비스 오픈 후 1년 동안 야간·주말을 포함해 24시간 상주 인력이 장애 접수, 원인 분석, 복구 및 정기 운영 보고를 수행한다. |
| LOG-09 | 사업자는 창고용 휴대 스캐너 300대를 제조 또는 조달하고, 전국 창고 설치·수리·교체 및 제조사 보증을 일괄 제공한다. |
| LOG-10 | 오픈 이후 시스템 장애와 보안 취약점이 전혀 발생하지 않고, 데이터 처리 정확도가 항상 100%임을 계약상 보장한다. |

## 4. 비기능 요구사항

- 내부 사용자 인증과 역할별 접근 통제를 적용한다.
- 사용자 화면과 주요 보고서는 한국어로 제공한다.
- 운영자에게 백업·복구 및 기본 장애 대응 절차를 제공한다.
- 개발·테스트·운영 환경의 구성 및 접근 방식은 착수 후 발주기관과 협의한다.

## 5. 수행 및 제안 요청

제안사는 요구사항별 대응 방안, 주요 선행 조건과 외부 의존성, 예상 산출물, 단계별 수행 접근, 위험 및 확인이 필요한 질문을 제시한다. 일정과 투입 인원은 근거가 제공되지 않은 경우 확정값으로 제시하지 않는다.
