Step6. 정리 및 마무리

RFP 분석·제안서·WBS 생성 사례를 통해 업무를 나누고, 실행 기능과 근거 자료를 연결하고, 결과를 검증하며 개선하는 에이전트 구성 방법을 살펴봤습니다. 같은 원칙을 다른 업무에도 적용할 수 있습니다.

1. 전체 구성 되짚기

이 에이전트의 업무 흐름은 분석 → Draft WBS → 제안서 → 상세 WBS입니다. 각 단계에서 요청 해석·계획·실행·검증·보완의 Agentic Loop가 동작합니다. GHCP는 이러한 다단계 흐름과 여러 Skill·도구 활용, PPTX·XLSX 작성 품질을 고려해 선택했습니다.

2. 각 구성에서 기억할 설계 기준

구성핵심 기준현재 에이전트에 적용한 방식
Instructions전체 목표·범위·공통 원칙·라우팅에 집중필요한 Skill을 순서대로 연결하고 청사진·인력·일정의 일관성 유지
Skill하나의 명확한 업무와 완료 기준을 정의분석·WBS·제안서를 분리하고 이전 결과를 재사용. 문서 생성은 동봉한 표준 양식을 복사해 작성·검증
Tool필요한 행동·입출력·원천·접근 범위를 기준으로 선택공식 기술 근거를 검색·조회하기 위해 Learn MCP 연결
Knowledge필요한 판단 정보·자료의 역할·최신성·검색 범위를 확인인력관리표로 실명 후보 추천, 기존 제안·WBS로 내용 참고. 공통·업무별 자료 구분
테스트·개선기대 동작과 실행 증거를 대조해 원인에 맞게 수정정상·입력 부족·변경·오류 상황 확인 후 Trace로 문제 지점을 찾아 재검증

공통 원칙과 작업별 방법을 중복 작성하면 수정할 때 충돌하기 쉽습니다. 전체 업무의 연결은 지침에, 구체적인 수행 방법은 Skill에 두고 Tool·Knowledge는 그 업무에 필요한 기능과 근거를 제공하도록 구성합니다.

3. 결과를 평가할 때 놓치지 않을 점

01 · 근거

근거가 있는가?

출처가 실제 판단을 뒷받침하는가?

02 · 일관성

같은 값을 유지하는가?

단계 간 ID·내용·상태가 이어지는가?

03 · 업무 기준

업무 조건에 맞는가?

필요한 내용·형식·처리 조건을 충족하는가?

04 · 실제 완료

실제로 완료했는가?

호출·처리·파일 제공을 확인했는가?

05 · 수정·검증

원인에 맞게 고쳤는가?

문제 지점을 보완하고 다시 확인했는가?

4. 자신의 업무에 적용하기

여섯 칸에 핵심 내용을 적어 업무의 목표와 구성을 정리해 봅니다.

어떤 요청을 처리하고 어디까지 맡길까요?

독립된 목적과 완료 기준을 가진 작업은 무엇인가요?

각 작업이 받아야 할 정보와 유지할 값은 무엇인가요?

어떤 기능과 자료가 필요한가요?

어떤 결과를 받아야 업무에 쓸 수 있나요?

어떤 증거를 확인하고 어디를 고칠까요?

입력 내용은 자동 저장되지 않습니다. 필요한 내용은 별도로 복사해 보관하세요.

다른 입력에 대한 적용을 확인하려면 RFP-02 또는 RFP-03을 사용해 봅니다. 현재 대화의 결과를 그대로 반복하는지보다, 새 요구사항에 맞게 판단하면서도 정의한 역할·근거·완료 기준을 유지하는지 확인합니다.
